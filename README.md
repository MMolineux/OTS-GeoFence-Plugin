# GeoFence Plugin for OpenTAKServer

Enable server-side GeoFence monitoring to trigger custom notifications.

Although ATAK and WinTAK have built-in support for GeoFence alerts, a server-side monitoring process allows you to:

- Monitor "headless" TAK sensors and clients without the requirement for the fully-fledge ATAK or WinTAK runtime.
- Configure custom notification channels such as webhook, email or SMS
- Setup more complex GeoFence triggering conditions (e.g. only trigger if both Bob and Alice have entered the geofence)
- Centrally manage GeoFences

Powered by [Tile38](https://tile38.com)

## Features

- Automatically register GeoFences when created by native ATAK and WinTAK clients.
- Toggle between `Report-Only`, `Active` and `Inactive` modes
- Complex GeoFence triggering conditions using Javascript-like expressions (see https://tile38.com/topics/filter-expressions#expressions)
- Notification via webhook, email, sms and rabbitmq
- Conditional notification based on event context (callsign, date/time, EUDs, etc...)

## Usage

GeoFences are created manually within OpenTakServer or automatically when native `__geofence` events are generated by TAK clients.

There are 4 modes:

- `Active`: GeoFence events will be logged and notifications are sent (if notification conditions are met)
- `Report-Only`: GeoFence events will _only be logged_, configured notifications are ignored.
- `Inactive`: GeoFence is not being monitored by the server and no events are logged.
- `Archive`. GeoFence was 'soft-deleted' by OpenTakServer or a TAK client, and may be _restored_ or permanently deleted. The GeoFence event log is also retained for a configurable amount of time.

Automatically created GeoFences begin in `Report-Only` mode, until at least one notification is configured within OpenTakServer, so as to not interfere with the existing TAK ecosystem (e.g. double up on alerts).

## Under the hood

This plugin binds to the existing `cot_controller` rabbitmq _fanout_ exchange and listens for CoT events.
